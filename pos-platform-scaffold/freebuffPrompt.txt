From the Daraja developer portal (developer.safaricom.co.ke — create a free account, then create an app; sandbox credentials appear on the app's dashboard):

Consumer Key — the app's public identifier, used to ask for an access token.
Consumer Secret — the password that goes with that key. Treat it as a real secret.
Shortcode — the number money lands in. In sandbox this is Safaricom's shared test number (174379); in production it's your own paybill or till number, issued after you sign the M-Pesa agreement.
Passkey — a shared secret that pairs with the shortcode to sign each payment request. Sandbox has a published test passkey; production gets its own.
For production you'll also need Safaricom to enable the M-Pesa Express (STK Push) scope on the app — sandbox has it by default.

Callback token — not from Safaricom. It's a random string that goes into the payment-prompt URL we hand to Daraja, so our callback endpoint can prove an incoming notification is genuinely ours and not someone poking at it. Make one strong value yourself (openssl rand -hex 32 or a password manager), and save the same string in both places.
